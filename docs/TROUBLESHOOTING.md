# DSH 便携版 · 排错手册（TROUBLESHOOTING）

> **这是什么**：DSH 便携版把 DeepSeek Harness（官方 npm 包 `@deepseek-ai/dsh`，带 Web UI）连同官方 Node v22.23.1 运行时打成一个 Windows 便携文件夹，**解压双击即用，不需要装任何东西**。
> **运行要求**：64 位 Windows 10 **1809 (Build 17763)** 及以上，或 Windows 11。
> **包内入口**：**`启动 DSH.vbs`**（主推）、`start-dsh.cmd`（备用）、`DSH 便携版.exe`（可选图形界面）。
> **默认端口**：**3080**。**包内最长相对路径：197 字符。**

这份手册只记录**真实踩过的那 9 个问题**，每个都按「**现象 → 原因 → 怎么做 → 怎么验证真的好了**」写。
它不是教程，是**翻查表**：先看下面的速查表，直接跳到对应的那一节。

---

## 先试这三步

大部分问题，试完这三步就好了。三步相互独立，**哪一步看着像你的情况就先做哪一步**。

### 第一步：换入口 —— 用 `启动 DSH.vbs`，别只依赖 exe

- **双击 `启动 DSH.vbs`**（主推入口）。它走的是 Windows 自带、**微软签名的 `powershell.exe`**，不会被「智能应用控制」拦，也不会弹「未知发布者」。
- 如果这台机器上 `.vbs` 的文件关联被改坏了、双击没反应，就用 **`start-dsh.cmd`**（备用入口，效果一样，只是会多出一个黑窗口，是正常的）。
- **`DSH 便携版.exe` 是可选入口，不要把它当唯一入口。** 它是新编译、未签名的程序，在这类安全策略下随时会被拦 —— 见 **T1**。

### 第二步：换短路径 —— 把整个文件夹解压到 `C:\DSH`

- 包内**最长相对路径有 197 字符**，你放的目录一深，加上去就超了，程序会报错。
- **解压到 `C:\DSH`、`D:\DSH` 这种短路径**。别放桌面，别放 `C:\Users\名字\Downloads\新建文件夹\……` 这种又深又长的目录 —— 见 **T5**。

### 第三步：解除锁定 —— 右键 → 属性 → 解除锁定

- 从压缩包里解出来的文件，Windows 会打上「**此文件来自其他计算机**」的标记，exe 可能直接跑不起来或被拦。
- **右键该文件（或整个文件夹）→ 属性 → 常规 → 底部「解除锁定」→ 确定** —— 见 **T2**。
- **不要在压缩包窗口里预览着直接双击运行**，先把包完整解压出来。

## T1 exe 被智能应用控制拦截

**现象**

双击 `DSH 便携版.exe`，弹窗：

> 应用程序控制策略已阻止此文件 (WinError 4551)

而且**同一份代码，第一次编译出来的 exe 能跑，重新编译之后同一类 exe 又被拦**。

**原因**

Windows 的**智能应用控制（Smart App Control）**会拦**新编译的、没有签名（或签名不受信任）的 exe**。便携包里的 exe 是自己编译的，正好落在这条策略上。

**怎么做**

1. **直接用 `启动 DSH.vbs`，或者 `start-dsh.cmd`。** 这两个入口走的是**微软签名的 `powershell.exe`**，永远不会被这道策略拦。这是**正确的解法**，不要跟 exe 死磕。
2. 下面这些办法**实测过、但不能稳定解决**，别在上面浪费时间：
   - 把 exe **复制到别的目录** —— 不行。
   - **清掉文件附加流**（Zone.Identifier / SmartScreen 标记）—— 不行。
   - 用**自签证书重签** —— 不行；同一份代码首次编译能跑，重新编译后又被拦。
3. **自签证书 + 在「受信任的发布者」里信任这个证书**，能让**一部分**场景放行。可以当补充手段，**但不能作为唯一入口** —— 入口必须是 `.vbs` 或 `.cmd`。

**怎么验证真的好了**

双击 `启动 DSH.vbs` → 出现启动器窗口、开始环境预检 → 浏览器自动打开 `http://127.0.0.1:3080` 且页面正常。之后就一直用这个入口，别再双击 exe。

## T2 exe 解压后被拦或提示「此文件来自其他计算机」

**现象**

从压缩包解压出来的 exe，一运行就被拦，或弹「此文件来自其他计算机」的提示。

**原因**

解压工具会给解压出来的文件加上 **Zone.Identifier 附加流**（记录「这文件来自网络」）。Windows 看到这个标记，对 exe 的处理会更严格。

**怎么做**

1. **单个文件**：右键该文件 → **属性** → 「常规」标签页 → **底部勾选 / 点击「解除锁定」** → 确定。
2. **整个包**：可以**整包解压之后**，对出问题的文件（或整个文件夹里的文件）做同样操作 —— 右键 → 属性 → 解除锁定。
3. **不要直接在压缩包预览窗口里双击运行**。先完整解压到一个短路径目录，再运行。

**怎么验证真的好了**

- 再看一次文件属性：「常规」标签页底部那段「解除锁定」的提示已经消失（或者你已经勾上并确定）。
- 再双击该 exe，**不再弹「此文件来自其他计算机」**。
- 如果解除锁定之后 exe 仍然被智能应用控制拦下，那就是 **T1**，回到 `.vbs` 入口即可。

## T3 端口 3080 被占用

**现象**

启动器提示：

> 端口 3080 被占用(PID xxxx)

**原因**

**3080 已经被别的程序监听**，或者本便携版上一次的服务没退干净。

**怎么做**

1. **查是谁占的**：打开命令提示符，执行

   ```
   netstat -ano | findstr :3080
   ```

   记下输出**最后一列的那个 PID**（就是提示里的 xxxx）。
2. **结束它**：`Ctrl+Shift+Esc` 打开**任务管理器** → 「详细信息」标签页 → 找到 PID 等于上面那个数字的进程 → **结束任务**。
3. **或者，改用别的端口启动**：启动器在 3080 被占时会自动往后找可用端口（3081、3082……）并提示你，用它给的那个端口就行。

**怎么验证真的好了**

重新启动，启动器**不再报「端口被占用」**；浏览器能打开对应端口的 `http://127.0.0.1:<端口>` 且页面正常。再跑一次 `netstat -ano | findstr :3080`，确认监听 3080 的 PID 就是本便携版的（如果你选了换端口，那就确认 3080 上已经没有可疑进程）。

## T4 没填 `DEEPSEEK_API_KEY`

**现象**

启动没报任何错，但浏览器里提示未配置密钥，或者引导你填 API key。

**原因**

**没有配置环境变量 `DEEPSEEK_API_KEY`。**

⚠️ 注意：**这不阻止启动。** 包内也**绝不包含任何 API key**。

**怎么做**

让程序照常启动就行 —— 它会**照常起 Web 服务并自动跳转到浏览器**，你在**页面里按引导填入自己的 key** 即可。

**怎么验证真的好了**

在页面里填完 key 后**能正常发消息 / 对话**；刷新页面后依然有效。

## T5 解压到很深的目录导致报错

**现象**

把包解压到很深的目录后启动报错（路径过长相关），或运行时提示找不到文件。

**原因**

**包内最长相对路径有 197 字符**。Windows 的路径总长有上限，你的目标目录一深，加在一起就超了。

比如**不要**解压到这里：

```
C:\Users\名字\Downloads\新建文件夹\DSH-Portable\...
```

**怎么做**

- **解压到短路径**，推荐 **`C:\DSH`**（`D:\DSH` 也行）。
- 之后移动、重命名都行，但要保证**整个文件夹是完整的**（别只复制了一半文件）。

**怎么验证真的好了**

在新短路径下双击 `启动 DSH.vbs`：启动器**环境预检通过**、服务正常起来、浏览器能打开页面 —— 说明路径问题解决了。

## T6 浏览器里看到的是旧界面

**现象**

Web UI 打开后看到的还是旧界面，之前改过的东西看起来没生效。

**原因**

**浏览器缓存了旧的页面资源。**

**怎么做**

- 在该页面按 **`Ctrl + F5`**（强制刷新，绕过缓存）。
- 或者用**无痕 / 隐身窗口**重新打开地址。

**怎么验证真的好了**

界面显示的是新的；用无痕窗口打开看到的内容和强制刷新后一致。

## T7 杀毒软件报毒或删文件

**现象**

**360 / 火绒 / Defender** 报毒，或者直接把包里的文件**隔离 / 删除**掉。

**原因**

便携包里**含 Node 运行时和 exe**，很容易被杀毒软件的**启发式 / 云查杀**误报。

**怎么做**

1. 把**整个 DSH 文件夹**加入杀毒软件的**白名单 / 排除项 / 信任区**（360、火绒、Defender 都有这个设置）。
2. 如果文件**已经被删掉/隔离**了，先**重新解压补齐**这些文件，再加白名单。

**怎么验证真的好了**

加白之后重新解压、重新启动，**文件不再被删**，服务能正常起来；再对文件夹手动扫一次，**不再报毒**。

## T8 首次启动要等一会儿

**现象**

双击后窗口像是卡住 / 没反应，以为根本没启动。

**原因**

**第一次启动要起 Node 服务和 Web 服务**，需要一点时间。**这是正常的。**

**怎么做**

耐心等 **10–30 秒**。**这段时间窗口不要关。**

**怎么验证真的好了**

等一会儿后**浏览器会自动弹出**，或者启动器状态变成「服务已运行」；能正常打开 `http://127.0.0.1:3080`。

## T9 卸载 / 还原机器

**现象**

不想用了，想卸载干净，或者想把机器还原到装之前的状态。

**原因**

这个包是**绿色便携设计**：**不写注册表、不改 PATH、不动系统目录**，所以**根本不需要「卸载」**。

**怎么做**

1. **删掉整个文件夹就干净了。**
2. 如果它改过**自己的 profile 数据**，包内另有**一键还原脚本**，跑一下即可恢复。

**怎么验证真的好了**

- 删掉文件夹后，系统里没有残留：**PATH 里没有 DSH 相关项**，也没多出 DSH 的自启动项 / 注册表项。
- 跑完还原脚本后，**profile 数据回到初始状态**。

---

> 排错顺序建议：**入口（T1 / T2）→ 目录（T5）→ 端口（T3）→ 等一等（T8）→ 再谈别的**。
> 绝大多数「打不开」都止步于前两项。
